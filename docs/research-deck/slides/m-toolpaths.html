Toolpaths and slicing

From G-code to printed beads

parseGcodeToBeads(gcode)

Job turn G-code into a list of printed bead segments

In → Out plate_1.gcode → segments with start, end, width, height, feature type, layer

How

  • read G0 / G1 moves and G2 / G3 arcs; arcs are cut into short straight pieces [6]
  • track absolute (M82) or relative (M83) extrusion: a move that adds plastic is a bead, anything else is travel
  • comment tags set the context: ; CHANGE_LAYER, ; Z_HEIGHT, ; LAYER_HEIGHT, ; FEATURE (outer wall, inner wall, sparse infill, support…), ; LINE_WIDTH

Rule toolpaths are data, not a surface mesh; they become layer outlines first

slicePlanarSections(surface)

Job the older path: cut a CAD triangle mesh or STEP B-rep with flat planes

In → Out surface mesh → closed 2D cross-sections, grouped into slabs

Use now headless regression scenarios and the legacy preset path

From beads to one layer shape

buildLayerShape(segments)

Job turn the beads of each layer into one clean 2D shape, the “cookie”

In → Out segments → one polygon set per printed layer; outer loops counter-clockwise, holes clockwise

1 · Bead → rectangle one line width wide, ends extended by half a width

2 · Merge union of all rectangles of the layer with Clipper2, NonZero fill rule [7, 8]

3 · Close gaps grow by g, then shrink by g, with g half the median line width: seals tiny gaps between touching beads [9]

4 · Clean tiny “dust” loops are removed; the infill pattern stays as real holes in the shape

p₀, p₁ bead ends · t̂ unit direction · w line width · w̃ median line width · grow / shrink = polygon offset outward / inward

Real modules: GcodeToolpathLoader + ToolpathModel (parser), ToolpathSections (layer shapes), LayerSlicer + StepSlicer (older CAD-plane path). The cookie of each layer is the input to the slab mesher on the next slide.
