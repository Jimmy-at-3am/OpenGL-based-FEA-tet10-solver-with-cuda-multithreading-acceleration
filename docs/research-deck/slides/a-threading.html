Appendix 2 · Separating the front end from heavy work

Solver core · before May

Background jobs · 13 Jul

Separate solve process · 6 Sep

Problem

building K was the slowest part of a solve

slicing, meshing and solving dense G-code parts took tens of seconds; the window froze and nothing could stop it

long fracture runs could not be stopped, and closing the app waited for them

Thinking

split the elements across cores without making them wait on each other

move the work to a worker thread; only the render thread may touch OpenGL

a thread cannot be killed safely, and an opaque library call ignores cancel checks, so the solve needs its own process

Solution

OpenMP assembly into separate blocks, no locks

a compute job with progress and a cancel flag checked at stage, layer and iteration boundaries; GPU buffer uploads deferred to the render thread

a worker process with live status in shared memory; Pause / Resume / Keep results; a close-during-run dialog

Result

same answer, faster

the app stays responsive; a cancelled TetGen call is discarded after it returns

the window, the stop control and the heavy compute no longer share a thread

Render / UI thread

input, 3D view, inspector, OpenGL uploads, Pause and Hard Stop buttons

Worker thread

slicing and meshing; never calls OpenGL; cancel flag

Worker process

every solve, multithreaded or on the GPU; can be ended at any moment
